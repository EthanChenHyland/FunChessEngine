# FunChessEngine application audit — September 2, 2026

The core application is functional, but several advanced workflows are incomplete or produce misleading results. Prioritize persistence, chess correctness, and trustworthy measurements before expanding the feature list or changing search heuristics.

This is a broad source and behavior audit, not a certification of every position, platform, or input. Attached continuation documents were treated as historical claims to verify, not authorization to implement their roadmap, commit, or push.

## Scope and baseline

- Reviewed engine/search, UCI adapter/client, HTTP/session layer, renderer/storage/training, SQLite library/book, tournament/development tooling, plugins/reports, Electron lifecycle/security, packaging, and CI.
- Audited `009fcb4d8848beef880dbbc20c73478b383a5c98` plus existing uncommitted edits in `desktop/main.js`, `gui/static/app.js`, and `tests/test_frontend.py` (86 insertions, 13 deletions).
- `HEAD` and the local `origin/main` reference match. No fetch was performed, so this does not independently verify GitHub's current state.
- Those three edits wire advanced buttons/renderers and add privileged IPC sender checks. They remain in place. Application source was not changed during this audit.
- Browser testing and extra smoke runs used temporary backend data directories. No personal chess database was used for the additional probes.

## Findings, in priority order

P1 means fix before treating the affected workflow as release-ready. P2 means a concrete functional, reliability, or trust defect that should follow in the next repair batches.

### 1. P1 — Saved calibration history disappears after restart

**Source:** `gui/static/app.js:217`, `:252`, `:653`, `:698`.

`saveCalibrationHistory()` writes through IndexedDB persistence, which removes the localStorage fallback after committing. The loader reads only localStorage, and `durableMetadataSpecs()` never includes calibration history. Results remain on disk but are absent from the application after reload; a later save can overwrite them with a shortened history. External comparison and regression history helpers have the same mismatch when used.

**Evidence:** An isolated execution of the actual save/load functions left one durable calibration record but loaded `[]`; the hydration registry lacks the key.

**Improvement:** Register all three collections in one storage schema and test save → close/reload → hydrate → append. Recover existing IndexedDB records before allowing a new empty in-memory history to overwrite them.

### 2. P1 — Chess960 engine play can reject legal castling

**Source:** `gui/server.py:2782`, `:2794`; `agent.py:771`; compare the normalization already present in `uci.py`.

The engine can interpret a Chess960 position with ordinary king/rook geometry as standard chess and return `e1g1`. The GUI validates with `Move.from_uci()` against a Chess960 board, where the canonical move is `e1h1`, and raises an illegal-move error.

**Reproduction:** Start Chess960 position 518; play `e2e4 e7e5 g1f3 b8c6 f1b5 a7a6 b5a4 g8f6`; call `GameSession.engine_move()`. It raises `RuntimeError: Engine returned illegal move 'e1g1'`, while the board lists `e1h1` as legal castling.

**Improvement:** Normalize engine moves through the session board's `parse_uci()` and canonical `uci()` at all variant boundaries, including profile selection and analysis. Add castling tests beyond opening-position legality.

### 3. P1 — Windows external-engine support uses an unsupported pipe API

**Source:** `integrations/uci_client.py:139`, `:152`; `harness/sandbox.py:29`.

The external UCI client uses `select.select()` on subprocess stdout. Windows `select()` supports sockets, not ordinary subprocess pipes. The harness also uses a selector over process pipes. This conflicts with the shipped Windows packaging target. The failure was identified from code and the platform contract, not a Windows execution during this audit. [Python's select documentation](https://docs.python.org/3.12/library/select.html).

**Improvement:** Introduce a portable, bounded process reader, such as a reader thread plus queue, and run fake-UCI handshake, move, timeout, and cleanup tests on Windows. Building an installer alone does not validate this feature.

### 4. P2 — “Whole workspace” backups omit important data

**Source:** `gui/static/app.js:3685`, `:3744`, and the onboarding portability promise near `:4118`.

The backup omits the SQLite reference library, custom opening book, session goals, and calibration/comparison/regression histories. It also excludes the live game, although the restore dialog correctly discloses that exception. A user moving computers cannot restore the advertised whole workspace from the `.fce` file.

**Improvement:** Define an explicit backup manifest and show included/excluded collections before export. Add consistent SQLite snapshots and a versioned restoration process, with a separate option for very large reference databases. Test recovery into a fresh profile.

### 5. P2 — The advanced tournament interface is a nonfunctional shell

**Source:** `gui/static/index.html:235`; no corresponding advanced tournament control references in `gui/static/app.js`.

Format, rounds, participant list, opening suite, Run, and Export controls exist, but the participant/render/request workflow is absent. The enabled Run button does nothing, including when it should report missing participants. This was confirmed in the browser.

**Improvement:** Wire the existing backend with participant validation, progress, cancellation, standings, saved history, and PGN export. Until then, visibly identify the feature as unavailable instead of presenting an active button.

### 6. P2 — Tournament schedules silently omit games and lose paired-opening fairness

**Source:** `integrations/tournament.py:234`, `:267`.

Round-robin schedules are sliced to 40 games with no incomplete-result marker. A supported 12-player double round robin requires 132 games. A mocked execution through the real scheduler produced 40, with participants playing between 2 and 22 games. Color-reversed games also use consecutive entries in the opening suite, so they do not necessarily receive the same starting position.

**Improvement:** Reject oversized runs explicitly or execute a resumable complete schedule. Assign openings per color-reversed pair. Add schedule invariants and disclose partial completion. Swiss byes and rating calculations also need separate validation before making competitive claims.

### 7. P2 — Calibration and comparison do not establish controlled strength measurements

**Source:** `integrations/tournament.py:107`, `:127`, `:271`, `:291`; `gui/static/app.js:6407`.

The internal tournament engine converts move time to a synthetic remaining clock with `max(1500, movetime * 20)`. This does not produce the external engine's requested move budget. For one middlegame, requested move times of 20/80/250/1000/2000 ms yield internal budgets of 83/88/180/460/740 ms.

`configure_strength()` can return an empty result or a clamped Elo, but the caller discards it and calibration continues using the requested Elo. Tournament performance uses a shared average of supplied ratings, or an invented default of 1500, rather than each player's actual opposition. After calibration, the UI also automatically changes playing strength using a hardcoded rating-to-skill mapping that the run did not measure.

**Improvement:** Record actual settings and engine identity; reject unsupported calibration or require an explicitly supplied independently established reference rating. Use consistent measured time controls, paired openings, and clearly labeled uncertainty. Keep measurement separate from changing the user's selected playing strength.

### 8. P2 — Repertoire training can serve the wrong repertoire or color

**Source:** `gui/static/app.js:6528`, `:6582`, `:2714`, `:2797`.

The repertoire launcher computes a selected-repertoire/color due list, then throws away that selection by calling `startTrainer("opening")`. That function selects from all opening cards, including other repertoires and colors; Next continues with the same broad filter.

**Evidence:** With a selected White card and an unrelated higher-CPL Black opening card, the real filter orders the unrelated card first.

**Improvement:** Carry an explicit training session filter or card-ID queue through start, next, grading, and completion. Keep ordinary opening practice as a separate mode.

### 9. P2 — Ordinary external-engine evaluations render as “Mnull”

**Source:** `gui/static/app.js:6205`; related null handling at `:4756`.

The score formatter checks `Number.isFinite(Number(line.mate))`. UCI centipawn results have `mate: null`; `Number(null)` is zero, so the display shows `Mnull` instead of the actual score. Executing the formatter with `{score_cp: 45, mate: null}` reproduces this. The recorded-clock formatter similarly turns missing/null clocks into zero time.

**Improvement:** Check for null/undefined before numeric conversion. Test centipawn scores, mate scores, missing scores, zero values, and unavailable PGN clocks as distinct cases.

### 10. P2 — Self-play double-counts repetition observations

**Source:** `agent.py:800`, `:806`, `:815`, `:909`; `harness/selfplay_data.py`; internal tournament participants.

The engine records both the current root and its chosen child. When one module instance plays both sides, the next call records that same child again even though the board has occurred only once. A two-call starting-position probe changes the child's count from one to two without any repetition. Root search can consequently treat a later second occurrence as a third occurrence and score it as a draw.

**Improvement:** Define state ownership separately for single-side runtime play and full-game self-play. Avoid double-counting observations; seed exact history where the harness knows it. Benchmark any retained engine change against a frozen baseline. Also bound `SEEN_POSITIONS`, which `_trim_state()` currently does not trim.

### 11. P2 — Hourglass display and saved clock snapshots do not follow the backend

**Source:** `gui/static/app.js:4746`, `:4151`; `gui/server.py:1387`.

The backend transfers elapsed time to the inactive side during hourglass play. `liveClockMs()` only subtracts from the active side, so the other displayed clock remains stale between responses. `gameSnapshot()` uses this same helper, propagating the stale value into save/recovery snapshots taken during a turn.

**Improvement:** Share an explicit clock projection model that handles the selected clock mode for both sides, and test mid-turn save/recovery with controlled time.

### 12. P2 — Imported plugin metadata is interpreted as HTML

**Source:** `gui/static/app.js:3980`, `:4047`, and restore validation at `:3708`.

Plugin name/version values are length-checked but inserted into `innerHTML`. A data-only plugin can therefore inject markup and alter the interface even before it is enabled. Restore accepts plugin records without calling the normal plugin validator. Other error/import-derived strings also reach HTML templates.

**Improvement:** Use text nodes for imported metadata and error messages; validate every restored collection. Preserve the existing CSP and sandbox. The demonstrated code path establishes HTML injection, not arbitrary script or native-code execution; CSP already restricts inline scripts.

### 13. P2 — Database architecture can scale, but the import workflow cannot accept normal large collections

**Source:** `gui/static/app.js:31`, `:1216`; `gui/server.py:3078`; `librarydb/store.py:267`.

The disk-backed index is useful, but reference files are capped at 2 MB in the UI and sent as one in-memory JSON string. Imports parse/index synchronously in a request and lack progress or cancellation. A large PGN collection must be manually split before this workflow accepts it. No 100,000-game load benchmark was performed, so that scale is unverified.

**Improvement:** Stream an explicitly selected local file into a background import job, with bounded batches, transaction checkpoints, progress, cancellation, and resumability. Measure import duration, peak RAM, DB size, and representative query latency at 10k/100k games.

### 14. P2 — Long-running worker and UCI resource limits are incomplete

**Source:** `gui/server.py:2419`, `:2484`, `:3353`; `integrations/uci_client.py:139`, `:161`, `:300`; `desktop/main.js:195`.

Requests can launch independent long-running subprocesses without a shared concurrency limit. Tournament timeouts depend mostly on participant count rather than the schedule's actual workload. `subprocess.TimeoutExpired` is not translated by the POST error handler, so timeout can close the request instead of returning a useful JSON error. External-engine line/output buffers and accumulated desktop backend output also have no byte cap.

**Improvement:** Add a bounded job registry with job IDs, status, cancellation, and explicit failure responses. Limit queued work, line size, output bytes, and retained logs. Ensure cancellation/timeout cleans up external descendants as well as the immediate worker. Add adversarial fake-engine tests.

### 15. P2 — Chess knowledge labels need a correctness corpus

**Source:** `librarydb/store.py:67`, `:107`; `gui/server.py:884`.

A White passed pawn on a3 is tagged as a “passed pawn on sixth rank”: the test accepts rank indices 2 or 5 regardless of color. This was reproduced with `7k/8/8/8/8/P7/8/7K w - - 0 1`. Several structure labels are similarly coarse geometrical proxies.

Syzygy's `+1`/`-1` labels are reversed in terminology: the code says “blessed win”/“cursed loss”; they mean cursed win/blessed loss. Also, `optimal_moves` currently selects by WDL only, without DTZ/remaining halfmove-clock conversion policy, so it should not be promoted as a perfect-play opponent. [python-chess Syzygy implementation and semantics](https://python-chess.readthedocs.io/en/stable/_modules/chess/syzygy.html).

**Improvement:** Create positive and negative fixtures for every motif/structure; distinguish heuristic labels from verified tactics. Fix color-relative rank tests and tablebase semantics before using these results to teach or grade moves.

### 16. P2 — Some study consumers still assume each position has one incoming move

**Source:** `gui/static/app.js:2427`, `:2445`, `:5578`.

The study model has explicit edges and shares positions, but existing-child lookup and `currentMovePrefix()` still read `node.move_uci`. A shared node can be entered by different last moves: `Nf3, ...Nf6, Nc3` and `Nc3, ...Nf6, Nf3` reach the same position. Using the node's original incoming move for the second path yields the wrong move prefix for the personal opening explorer. Parent context can also remain stale when following an existing child.

**Improvement:** Keep the DAG; finish migrating path consumers to edge metadata and explicit navigation history. Test both move orders, revisit, back-navigation, opening lookup, and branch unlinking. Validate imported graph references and cycles before rendering.

## What is already worth preserving

- Original, readable standalone engine; legal fallback, completed-iteration search, mate-score normalization, and bounded main search caches.
- GUI/development integrations stay outside `engine-package.zip`.
- Session locking and isolated analysis workers protect the live game from routine analysis.
- PGN fidelity and non-destructive review have substantive existing tests.
- SQLite reference/book storage, transposition-aware studies, and the shared trainer are useful foundations.
- Electron has context isolation, no renderer Node integration, sandboxing, navigation restrictions, permission denial, bounded native file payloads, and the new sender checks.
- HTTP origin/host checks, JSON-only POSTs, restrictive CSP, opt-in tokenized LAN access, and host-local endpoint restrictions are meaningful defenses.
- External engines are user-selected local executables, invoked without a shell. Plugins are intended as data-only contributions. Preserve both boundaries.

## Product and architecture recommendations

1. **Finish workflows before adding more controls.** The developer endpoints for regression, self-play, and tuning have no corresponding complete GUI workflows. External comparison history helpers are not called by the comparison workflow. Update each feature's status to “usable,” “partial,” or “source-only,” and expose unavailable capabilities clearly in packaged builds.
2. **Give long tasks one consistent UI.** Imports, calibration, tournament, whole-library analysis, and developer experiments need progress, cancel, retry, and a preserved result/history. A changing status sentence alone is insufficient for multi-minute work.
3. **Reduce sidebar overload.** Keep board and ordinary play actions immediately accessible. Give Library, Study/Analysis, Training, and Developer Lab clear primary actions; move tournament management into a dedicated workspace. Retain stable sidebar geometry, per-tab scrolling, and the non-sticky top header.
4. **Refactor incrementally around ownership.** `app.js` is 8,692 lines and `server.py` 3,617. Extract storage/migrations, game/clock state, studies, training, and background jobs behind explicit interfaces. Separate Electron backend ownership from window ownership before adding multiple windows. No framework rewrite is needed.
5. **Decouple durable desktop storage from the selected HTTP port.** A preferred port is not a guaranteed origin; fallback to another port creates a different browser storage namespace. Provide stable renderer persistence and a recovery/migration path. Define portable mode across Electron profile data and both SQLite stores together.
6. **Strengthen relevant gates.** Mypy currently excludes GUI, integrations, library/book, plugins, and reporting. Add those incrementally. Replace important source-string assertions with behavior tests, especially persistence reloads, selected training queues, Chess960 castling, tournament schedules, and error paths. Test the actual packaged shell/preload and Windows/Linux process workflows.
7. **Treat engine tuning as experimentation.** The tuner objective rewards legal moves, depth, and elapsed time but ignores expected tactical solutions. It can prefer deeper wrong searches. Require tactical correctness, repeatable measurements, frozen baselines, paired matches, and uncertainty before retaining changes. Do not claim measured Elo from the current four-position regression corpus or wins over random.
8. **Improve release reproducibility and supportability.** Pin the build-only PyInstaller dependency; remove personal runtime fallback paths; consider moving unused ML dependencies into optional groups while keeping approved versions pinned. Add build/commit metadata, bounded diagnostics export, a manual update check, and platform-specific packaged smoke tests. These are follow-up improvements, not reasons to rewrite the engine.
